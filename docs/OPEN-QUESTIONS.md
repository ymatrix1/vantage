# Open questions

| # | Question | Notes |
|---|---|---|
| Q1 | **Work item boundaries.** When does one session's work become two items, or two sessions' work become one? | Rules accepted (D25) in [work item model](specs/work-item-model.md#boundary-rules). R1: over 96% of edit sessions have a key, branch or worktree; half change branch mid-session, so see D54 ([baseline](research/baseline.md#mapping-to-an-anchor-q1-d25)). |
| Q2 | **Ghost detection quality.** How to propose ghosts from chat without flooding the board? | Probably an LLM proposal with user confirmation, capped per day. R1: about 18% of prompted sessions are strict candidates, roughly 0.9 a day ([baseline](research/baseline.md#ghost-candidates-p3-q2)); precision still unlabeled. |
| Q3 | **Proof strength.** Is L1 (a qualifying check passed after the last edit) enough for Proven, or should the default be L2 (the check touches the changed code)? | Levels defined in the [proof spec](specs/proof.md#strength-levels). Start at L1. R1: 43.5% of edit sessions end with no L1; among L1 sessions a file-name proxy suggests 85% could reach L2 ([baseline](research/baseline.md#unproven-edits-p2-q3)). Re-measure with hook data. |
| Q4 | **Judgment model.** Jev, a small LLM, or rules only? | Compare on ~100 labeled examples. Check company data policy first. |
| Q5 | **Monitoring source.** Which tools are actually in use (Datadog, Sentry, PagerDuty, Grafana, dbt Cloud alerts)? | Determines the first monitoring adapter. |
| Q6 | **Deploy signal.** Do the main repos use GitHub deployments, Actions environments, or something else? | Needed for Shipped. |
| Q7 | **Monitoring window length.** Default 2 days; per repo? | Data pipelines may need a longer window. |
| Q8 | **UI host.** Localhost page, VS Code panel, or desktop app mod? | Start with localhost; revisit after Phase 2. |
| Q9 | **Codex live events.** Is tailing session files enough? | Yes for v1 (see [ingestion](specs/ingestion.md)). Revisit if Codex adds hooks. |
| Q10 | **Slack, Jira and Linear access.** API tokens vs. MCP connectors; rate limits; company approval. | Needed before Phase 6. |
| Q11 | **Stop hook strictness.** When, if ever, should the gate block (exit 2) instead of warn? | Warn only until false positive rate is known. Warn and block mechanics are settled by research [R2](research/claude-code-hooks.md#3-stop-hook-warn-vs-block) (D60); the policy question stays. |
| Q12 | **Slack app approval.** Will the workspace admin allow a custom Slack app (Socket Mode, user-scoped events)? | If not, fall back to search polling with a user token, or the Slack connector through a scheduled agent. |
| Q13 | **Webhook relay.** Is a hosted relay for GitHub, Jira, Linear and monitoring webhooks acceptable under company policy? | Off by default; polling alone works. |
| Q14 | **Reviewing others' PRs.** Should `review_request` items appear on the main board or only in Focus and the digest? | Proposal: Focus and digest only, to keep the board about own work. |
| Q15 | **Multiple machines.** Is one laptop enough, or is sync needed later? | Out of scope for now. |
| Q16 | **Context inference.** How to assign repos to Work or Personal automatically (path, GitHub org, git email)? | Proposal: GitHub org first, then path; user can override. |
| Q19 | **Behavior extraction.** Should agents propose behaviors from prompts automatically, or only from tickets and the user? | See [behaviors spec](specs/behaviors-and-detectors.md). |
| Q21 | **Why tree without a ticket.** How to draft "why we built it" from chat without inventing reasons? | Only from the user's own words and decisions, each node citing them; the user confirms before it's frozen. |
| Q22 | **Companion character.** Still needed now that every item is a character? | Keep optional; decide after testing the landscape. |
| Q23 | **Ping thresholds.** Are 4 working hours (owed reply) and 2 working days (follow-up) right? | Tune with real data; allow per-person overrides for key collaborators. |
| Q24 | **"Run in Vantage" mode.** Should Vantage optionally launch sessions itself (stream-JSON protocol or Agent SDK), like Vibe Kanban, to answer permission prompts and send diff comments from its UI? | It uses headless `-p` and moves toward running agents (a non-goal), so observing stays the default. See [Vibe Kanban research](research/vibe-kanban.md). |
| Q25 | **Embeddings and vector search.** Should a local embedding layer (small on-device model plus `sqlite-vec`) power ghost detection, suggested links for unanchored sessions, decision and mention dedupe, and similar-work estimates? | Not in v1; SQLite FTS5 covers search. Decide from R1: if many sessions map to no anchor, test it. Local only, suggestions only, never moves a stage. |
| Q26 | **GitHub notification residuals.** How long is the delay from an event to the thread bump? Does the list drop threads from an SSO org the token isn't authorized for? Do `ci_activity` notifications arrive with the web Actions setting on? | R4 couldn't create events or an unauthorized org (read-only). Measure delay in Phase 1 by logging both timestamps; test SSO with a deliberately unauthorized token. See [GitHub research](research/github.md#not-verified). |
| Q27 | **Headless limits.** How do `claude -p` and `codex exec` behave when a plan limit is hit, and does `-p` share the interactive 5-hour and weekly buckets? | Not documented and not observed in R13; treat any error as fall back. Tracked in `vantage-7xb3`. See [Explain engine research](research/explain-engine.md). |
| Q29 | **Code tab coverage.** Does the desktop app (Code tab) show the status line, and does user-settings `env` enable OTel there, or only managed settings? | Unverified; follow-up bean `vantage-2vdj`. Hooks do run there. |
| Q30 | **Versioned derived data.** Should Vantage keep the store in a versioned database such as [Dolt](https://github.com/dolthub/dolt) (git-like branch, merge and diff of tables, MySQL protocol, a separate server process) instead of SQLite (D17)? | Not for Phase 1 or 2: events are already append-only (D33) and `stage_changes` records transitions, so diff and history exist, and Dolt would add a binary and a server to the one-command install (D63). Revisit for a team mode with shared state that must merge between people, or if time travel over derived tables becomes a real need. Checked: repository facts only (Apache-2.0, Go, Windows binary 22 to 43 MB); not run. |
| Q31 | **Query builder or ORM.** Should the daemon use a typed query builder or ORM (Kysely, Drizzle, Prisma 7) instead of hand-written SQL on `node:sqlite`? | Not now. Prisma 7 needs a driver adapter (its SQLite example uses the native `better-sqlite3`) and a generated client with `prisma generate`; Drizzle and Kysely add dependencies and, for `node:sqlite`, only a community dialect (Kysely: `kysely-node-native-sqlite`, `@takinprofit/kysely-node-sqlite`), all against the one-command install (D63) and few dependencies (D66). Migrations stay hand-rolled but are being hardened (one file each, checksums, numbering check). Revisit if the Track query API (filters, sort, paging) becomes too dynamic for allow-listed SQL, or the schema passes about 25 tables; then evaluate Kysely first and check the dialect's maintainer and last release. Read from documentation pages and search results only; nothing was installed or run. |
| Q32 | **Archived while unfinished (P13).** Can Vantage learn that the app archived or closed a conversation, or only infer it? | Seen on the author's own use: the Claude desktop app archived sessions when their PR merged (`auto_archive_on_pr_close`) while follow-ups remained. No hook reports an archive, so Vantage can only infer it (a stopped or quiet session with open tasks, unproven edits or flags). Mitigation today: turn the app setting off. Check whether the app exposes session state locally; if it does, read it read-only. Flag `left_unfinished` is specified in [flags](specs/flags.md). |
| Q33 | **Search inside session text.** How should the Track search read the text of sessions? (A) a local full-text index (SQLite FTS5) in the store; (B) scan the transcript files when a query runs; (C) metadata only, as now. | To decide later. Data stays on the machine, so privacy is not the blocker; the choice is about cost (index size and upkeep, or query time), freshness and what a result shows. Bean `vantage-81ok`. |
